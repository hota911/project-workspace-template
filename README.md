# 個人のプロジェクトと文書管理

本人とエージェントが、個人の複数プロジェクト、関係者や知識の文書、作業記録を管理するフォルダである。

## 使い始める

1. このフォルダを新しい管理用フォルダへコピーする。`.git/` を除く隠しファイルも含め、既存フォルダを上書きしない。
2. この README の管理する内容と [開始時チェックリスト](onboarding.md) を記入する。未確認の項目はそのまま残す。
3. `projects/_template/` を `projects/<project-slug>/` へコピーし、プロジェクト概要を記入する。以下の一覧にリンクを追加する。
4. [TODO.md](TODO.md) に実行するタスクを記入する。
5. 作業日に `logs/_template.md` を `logs/YYYY-MM-DD.md` へコピーする。同日分があればそのファイルを更新する。
6. 稼働時間は `logs/time/_template.csv` を `logs/time/YYYY-MM.csv` へコピーして記録する。同じ月のファイルがあれば、そのファイルを更新する。

コピー先のルートを Codex または Claude Code の作業フォルダとして開く。
最初に「共通ルールと README を確認し、TODO と今日のログの記録先を示してください」と依頼する。
Claude Code では `/context` で `CLAUDE.md` の読み込みを確認する。
共通ルールは [AGENTS.md](AGENTS.md)、Claude Code の入口は [CLAUDE.md](CLAUDE.md) に置く。

ローカルフォルダだけで利用できる。
Git を使う場合、外部へ送る前に情報管理の条件を確認し、新しいリポジトリは private とする。
`.gitignore` は未追跡ファイルの除外に使うものであり、機微情報の送信可否を判断するものではない。

## 記録先

- [TODO](TODO.md)：期限、確認待ち、次に実行すること。
- [docs/](docs/README.md)：プロジェクトをまたいで参照・更新する関係者や知識などの Stock 型の文書。
- 各プロジェクトの README：現在の状況、範囲、成果物、重要なログへのリンク。設計や調査などの固有の文書も同じプロジェクト内に置く。
- [日別ログの雛形](logs/_template.md)：`logs/YYYY-MM-DD.md` に、その日の作業予定、実施結果、判断を記録する。単発作業もここに含める。
- [稼働時間](logs/time/README.md)：`logs/time/YYYY-MM.csv` に月ごとに記録する。
- [大きな作業の雛形](logs/_work-template.md)：詳細が長くなる作業は `logs/YYYY-MM-DD-<作業名>.md` に独立させる。日付は開始日とし、複数日にまたがる場合も同じファイルを更新する。各日の日別ログには進捗の要約とリンクを残す。

作業の経緯はログへ、繰り返し参照する知識や現在の方針は `docs/` または対象プロジェクトの文書へ反映する。
実行するタスクは TODO.md で管理し、ログに別のタスク一覧を作らない。

稼働時間は月別 CSV に集約する。開始・終了が分かる場合も、作業時間だけ分かる場合も記入できる。Markdown には重複して記録しない。
請求情報が必要な場合は [開始時チェックリスト](onboarding.md) に方法を記録する。
自動集計や外部サービスとの同期は含まない。
